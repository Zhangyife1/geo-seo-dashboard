# GEO 看板指标口径说明

本文档定义看板每个核心指标的计算口径、数据来源、更新频率与已知局限，是数据可信度的依据。

## 一、数据来源三态

| 状态 | 判定条件 | 页面表现 |
| --- | --- | --- |
| `real` | `CitationRecord.data_source` 为 `api` 或 `browser`（官方 API / 浏览器真实采集） | 正常展示，计入真实口径 |
| `simulated` | 数据来自搜索兜底（`search`）或模拟生成（`simulated`） | 标记“模拟”，不计入真实口径 |
| `demo` | 完全无采集记录，导出时注入种子数据 | 标记“演示”，不计入真实口径 |

> 注意：`real` 平台也可能出现 0 提及——这代表“真实采集到了回答，但品牌未被提及”，属于有效数据，不应与“未采集”混淆。

## 二、核心指标定义

### 1. AI 可见性指数（`ai_visibility_index`，0-100）

- 口径：当日在指定平台集合上各平台 `visibility_score` 的平均值。
- 平台可见性公式（`nlp_analyzer.calculate_daily_metrics`）：
  `引用率 × 0.4 + 情感正向度 × 0.3 + 推荐度 × 0.3`
- 局限：权重为启发式设定，未经过业务转化率校准。

### 2. AI 引用率（`citation_rate`，%）

- 口径：该平台当日回答中“品牌被提及”的查询数 / 总查询数。
- 局限：提及 ≠ 推荐，也不等于被正面评价；推荐份额需单独看 `is_recommended`。

### 3. 品牌提及次数（`mention_count`）

- 口径：当日被判定提及品牌的回答条数（NLP 正则 + 别名匹配）。
- 局限：规则匹配对口语化/英文变体召回不足。

### 4. 情感好感度（`sentiment_score`，0-100）

- 口径：各记录 `avg_sentiment`（-1~1）平均后映射 `(avg+1)*50`。
- 当前实现：规则关键词计数（`NLP_CONFIG.sentiment_model=fallback`），可选 transformers 模型未启用。
- 局限：关键词法对反讽、隐式否定不敏感。

### 5. AI 引荐流量（`referral_traffic`）

- 口径：`提及数 × max(1, 11 - 平均引用排名) × 15` 的估算值。
- **重要**：这是相对指数，不是 GA/统计埋点的真实流量。真实归因需接入 UTM + 落地页问卷。

### 6. 结构化数据健康度（`structural_health`）

- 口径：当日 `authority_score` 的平均值（信源权威信号比例）。

### 7. 引用排名（`citation_rank`，1-10）

- 口径：品牌首次出现在回答中的位置比例映射（前 5%→1，每 10% 递增一档）。
- 局限：这是启发式估算，不是平台官方排名。

## 三、KPI 环比（`kpi_changes`）

- 口径：近 7 天均值/总量 vs 前 7 天均值/总量，百分比变化。
- 数据要求：至少 14 天历史，否则返回空。
- 双口径：`kpi_changes`（全部平台）、`kpi_changes_real`（仅真实平台）。

## 四、趋势数据（`/api/v1/trend`）

- 导出时仅基于 `real` 平台构建，来源标记 `trend_source`；
- 无真实平台时返回空数组，前端显示“暂无真实趋势数据”，不再展示写死的 W1-W12 假曲线。

## 五、更新频率与可追溯性

- GitHub Actions 每天 UTC 03:00 采集 → 导出 JSON → 提交；Render 自动重新部署。
- 原始 AI 回答保存在 `CitationRecord.raw_response`，可通过 `/api/v1/tasks` 关联任务追溯。
